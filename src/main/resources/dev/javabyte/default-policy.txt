# JavaByte default host policy
#
# Guest bytecode is interpreted. When it calls into the JDK, the call runs for real ONLY if a
# rule below allows it. Everything else is answered by a stub or blocked and reported.
#
# The test for adding a line here: can any member it exposes read or change something outside
# the emulator's own memory (disk, network, processes, threads, the JVM itself)? If yes, it must
# not be listed; give it a stub instead. Syntax is documented on dev.javabyte.host.HostPolicy.

# Loading methods are stubs whatever the receiver. A JDK method that takes a loader is blocked by
# the router, because it would ask the loader for classes from inside host code. new
# URLClassLoader(...) is a stub that returns a loader which only remembers its URLs. <init> stays
# listed so that a sample's own subclass can be built, but on a simulated base, never on the real
# class: its real parent is the bootstrap loader and it answers JDK code only from the sample.
java/lang/ClassLoader#<init>
java/security/SecureClassLoader#<init>
java/net/URLClassLoader#<init>,getURLs
# Building a command is harmless; start() is a stub and never launches anything.
